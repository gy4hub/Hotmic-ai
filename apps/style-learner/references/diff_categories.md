# 7类修改的定义、示例与识别规则

本文档是 `hotmic-style-learner` 的核心分类参考。
`classify_edit.py` 和 `rule_extractor.py` 依据本文档的标准对修改进行分类和规则提取。

---

## 分类总览

| 类别代码 | 名称 | 核心问题 |
|----------|------|----------|
| `tone` | 语气调整 | 怎么说（情绪/温度/力度）|
| `structure` | 结构重排 | 说话的顺序和组织方式 |
| `fact` | 事实修改 | 说什么（信息本身的变化）|
| `wording` | 措辞偏好 | 用哪个词（固定替换模式）|
| `length` | 篇幅调整 | 说多少（增删内容量）|
| `platform` | 平台适配 | 针对特定平台的语气/结构/词汇调整 |
| `compliance` | 合规调整 | 删除或软化违规表述 |

---

## 一、tone（语气调整）

### 定义
语气调整指**同一意思**用不同的情绪强度、温度、立场来表达。
内容实质不变，但说话的感觉变了。

### 识别特征
- 把书面、中性的表述改得更口语、更有温度
- 把温和的表述改得更锋利、更有态度
- 添加或删除情感词（"确实""可惜""说实话"等）
- 改变句子的语气词（的/了/啊/呢）

### 示例

**书面 → 口语**：
```diff
- 这种做法存在一定风险，建议谨慎考虑。
+ 说真的，这种做法有问题，真的要三思。
```

**温和 → 锋利**：
```diff
- 这个方法可能对部分人有所帮助。
+ 说白了，这个方法对大多数人根本没用。
```

**中性 → 有温度**：
```diff
- 老年人应注意控制饮水量。
+ 家里有老人的，真的要注意，喝水喝多了反而伤身。
```

### 规则提取模式
- `tone-softening`：温和化，如"绝对"改成"可能"
- `tone-sharpening`：锋利化，如"建议"改成"你必须"
- `tone-colloquial`：口语化，如书面句改口语句
- `tone-warm`：添加温情表达

## 二、structure（结构重排）

### 定义
结构调整指**段落顺序**、**开头/结尾**、**论点排列**的改变，而非内容本身的改变。

### 识别特征
- 段落被移动到不同位置
- 开头被替换或新写（原开头被移到中间）
- 结尾被修改
- 多个小点被合并，或大段被拆分

### 示例

**调整开头**：
```diff
- 外泌体是一种细胞分泌的生物活性物质...（定义先行）
+ 花两万块打了外泌体，结果查出了肿瘤标志物升高...（冲突先行）
```

**调整论证顺序**：
```diff
- 原因 → 结果 → 案例
+ 案例 → 结果 → 原因（倒叙，更有冲击）
```

### 规则提取模式
- `structure-open-hook`：开头改为冲突/案例型
- `structure-reorder-logic`：论证逻辑顺序偏好
- `structure-merge-points`：倾向于将多个小点合并

---

## 三、fact（事实修改）

### 定义
事实修改指脚本中**具体信息**的增加、删除或修正。
包括数据、案例内容、引用来源的变化。

### 识别特征
- 数字/百分比被修改
- 具体案例细节被补充或删除
- 新增了一个信息点
- 删除了一个不确定的信息
- 来源被替换为更权威的来源

### 示例

**删除未验证数据**：
```diff
- 研究显示，外泌体对80%的患者有效。
+ 目前外泌体仍处于研究阶段，效果因人而异。
```

**补充数据**：
```diff
- 肌酐升高说明肾功能有问题。
+ 肌酐升高说明肾功能有问题。正常值：男性53-106，女性44-97（μmol/L）。
```

### 规则提取模式
- `fact-remove-unverified`：倾向于删除无来源数据
- `fact-add-ranges`：倾向于补充具体参考范围
- 注意：fact类修改通常是一次性修正，不抽取成通用规则

---

## 四、wording（措辞偏好）

### 定义
措辞偏好指创作者对**特定词汇或短语**有固定的替换倾向。
这是最容易形成"高置信度规则"的类别，因为替换模式是固定的。

### 识别特征
- 同一个词在多处被替换为另一个词
- 特定句式被固定的另一种句式替换
- 口头禅/惯用表达有规律地出现

### 示例

**固定词汇替换**：
```diff
- 但是...  →  不过...
- 然而...  →  但...
- 需要注意的是...  →  有一点要说...
```

**句式偏好**：
```diff
- 问：为什么...？答：因为...
+ 说白了，之所以...，是因为...
```

### 规则提取方法
1. 统计全文中同一词被替换的次数
2. 若同一词汇在≥2处被相同替换，提取为规则
3. 规则格式：`将"[原词]"替换为"[新词]"`

### 规则提取模式
- `wording-substitution`：固定词汇替换，如 "但是"→"不过"
- `wording-phrase`：固定短语偏好，如 "研究显示"→"有数据表明"

## 五、length（篇幅调整）

### 定义
篇幅调整指对**内容量**的增删，包括删除冗余、扩展不足、调整密度。

### 识别特征
- 大段被删除（不是因为合规问题）
- 某个论点被展开/补充
- 整体压缩或扩展了20%以上
- 重复表述被合并

### 示例

**删减冗余**：
```diff
- 这个问题很重要，真的非常重要，大家一定要注意，我再强调一遍，这个问题很重要。
+ 这个问题很重要，大家一定要注意。
```

**整体压缩**：
```diff
（删除了开头3句铺垫，直接从核心内容开始）
```

### 规则提取模式
- `length-platform-target`：平台字数偏好（如"视频号版控制在1000字以内"）
- `length-no-repeat`：不重复强调同一观点
- `length-trim-opening`：删除开头铺垫

## 六、platform（平台适配）

### 定义
平台适配指专门针对**视频号**或**抖音**差异的调整，包含语气、结构、词汇的组合变化。

### 识别特征
- 视频号版和抖音版之间的差异
- 针对特定平台的开头/结尾修改
- 特定平台的结尾CTA（行动号召）调整

### 示例

**抖音版开头优化**：
```diff
- 今天我想和大家聊聊外泌体这个话题。
+ 花两万块打外泌体，你知道风险是什么吗？
```

**视频号版结尾优化**：
```diff
- 评论区告诉我你的看法。
+ 如果你身边有需要的人，帮他们转一下这条视频。
```

### 规则提取模式
- `platform-douyin-open`：抖音版开头规则（必须冲突型）
- `platform-wechat-close`：视频号结尾偏好（转发导向）
- `platform-douyin-close`：抖音结尾偏好（评论互动导向）

---

## 七、compliance（合规调整）

### 定义
合规调整指删除或软化**违规表述**，包括诊断语言、疗效承诺、品牌推荐等。

### 识别特征
- 删除具体诊断性句子
- 把确定性表述改为或然性表述
- 删除品牌名
- 在数据后添加"来源"标注

### 示例

**诊断性删除**：
```diff
- 你描述的这些症状是典型的外泌体过敏反应。
+ 如果出现这类症状，建议及时就医。
```

**疗效软化**：
```diff
- 这个方法一定能降血压。
+ 这个方法对部分人有辅助作用，具体效果因人而异。
```

### 规则提取模式
- compliance类修改通常是强制规则，不需要学习置信度
- 但若创作者频繁修改同一类合规问题，说明AI初稿有系统性问题，记录并告警

## style_db.json 规则格式参考

```json
{
  "id": "style_001",
  "category": "wording",
  "rule": "将'但是'替换为'不过'",
  "confidence": 0.7,
  "source_diffs": ["20260318_exosome_diff01", "20260320_vaccine_diff03"],
  "created_at": "2026-03-18",
  "last_validated": "2026-03-20",
  "status": "candidate"
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，格式 `style_NNN` |
| `category` | string | 7类之一 |
| `rule` | string | 规则描述，必须清晰可执行 |
| `confidence` | float | 0.0-1.0，初始0.3，每次确认+0.2 |
| `source_diffs` | list | 该规则来源的diff记录文件名 |
| `created_at` | string | 首次创建日期 |
| `last_validated` | string | 最后一次被确认/修改的日期 |
| `status` | string | `candidate`/`confirmed`/`deleted` |

**status 状态机**：
```
candidate → confirmed（用户校准时确认）
candidate → deleted（用户校准时删除）
confirmed → deleted（用户校准时删除）
```

**confidence 调整规则**：
- 首次提取：`confidence = 0.3`
- 每次新diff确认同一规则：`confidence += 0.2`（上限 1.0）
- 用户手动确认（校准）：`confidence = 1.0, status = confirmed`
- 用户手动修改（校准）：`confidence = 0.8`
- 用户手动删除（校准）：`status = deleted`
