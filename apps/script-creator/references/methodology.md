# 口播脚本创作方法论

本文档是 `hotmic-script-creator` 的核心方法论说明。
任何兼容 AgentSkills 标准的 Agent 读完本文档后，应当能够完整执行七步创作法并交付9件套。

---

## 一、前置四件事（创作前必须锁死）

每次创作开始前，从 `shared/persona.json` 加载以下四项配置。
**这四项决定了所有创作决策的边界，不可跳过。**

### 1. 账号定位一句话

格式：`[身份] + [讲什么] + [讲给谁]`

示例：
- "前三甲医院主治医师，讲中老年常见病预防，讲给关心父母健康的子女"
- "10年营养师，讲科学饮食避坑，讲给追求健康生活的上班族"

**加载方式**：读取 `persona.json` 中 `positioning.one_liner`，若为空则在采访环节向用户确认。

### 2. 能力圈边界

明确两个列表：
- **能讲（can_discuss）**：创作者有专业背书、有亲身经验的话题
- **不碰（never_touch）**：超出专业范围、有法律风险、创作者明确回避的话题

**使用规则**：选题必须落在"能讲"范围内。若选题触碰"不碰"清单，必须在采访环节提示创作者并建议调整角度。

### 3. 双层受众模型

| 层次 | 定义 | 影响维度 |
|------|------|----------|
| 决策层 | 有能力转发/推荐/产生商业价值的受众 | 选题方向、深度 |
| 传播层 | 实际刷到视频的大多数人 | 语言风格、情绪调性 |

**使用规则**：
- 选题要能打动决策层（他们觉得"这个值得转给别人"）
- 语言要让传播层能听懂、有感触

### 4. 内容主线配比

记录不同内容方向的权重，如：
- 健康科普：50%
- 误区纠正：30%
- 个人故事：20%

**使用规则**：确保长期创作符合比例，当某条主线已明显过多时，优先推荐其他主线选题。

## 二、创作七步法

### 第一步：事实核查

**目的**：确保所有数据和事实有权威来源。

**操作规则**：
1. 识别脚本中所有具体数字、统计数据、研究结论
2. 每一条必须标注来源URL（期刊、官方机构、新闻媒体）
3. **不允许**出现无来源的具体数字（如"研究显示70%的人..."但没有来源）
4. 来源等级：
   - A级：同行评审期刊、官方政府文件
   - B级：权威媒体报道、知名机构报告
   - C级：个人博客、二手资料（须注明，谨慎使用）
5. 若用户已提供素材包（含来源），则验证素材来源等级后可跳过主动搜索

**输出格式**：
```
事实核查结果：
- [数据点1]：来源 [URL]（A级）✅
- [数据点2]：来源 [URL]（B级）✅
- [数据点3]：未找到权威来源 ⚠️ → 建议删除或改为模糊表述
```

---

### 第二步：采访定标（不可跳过）

**这一步是与"新闻搬运号"的本质区别。**

AI可以搜索整理信息，但无法提供创作者的独家视角、亲身经历、行业内幕。
采访环节确保每篇脚本都有"只有这个创作者才能说"的内容。

**操作规则**：
1. 根据选题和persona，提出2-3个关键问题
2. 问题方向参考：
   - "你在实际工作中见过最典型的案例是什么？"
   - "这个话题，你有什么是在网上看不到的判断？"
   - "你身边的人（同行/患者/客户）对这件事有什么误解？"
   - "你自己在这件事上踩过什么坑？"
3. 将创作者回答作为脚本的"独家素材"，在正文中用第一人称呈现

**示例问题**（医疗类账号）：
```
在创作前，我需要了解你的独家视角：
1. 关于[选题]，你在临床中最常见到什么情况？能说一个具体案例吗？
2. 大众对[选题]有哪些常见误解，是连医生也很难解释清楚的？
3. 你个人在这个话题上有什么判断，和教科书不一样的？
```

**重要**：不得在未收到回答的情况下自行编造"创作者独家视角"。

---

### 第三步：判定内容类型

根据选题和采访结果，判断本篇属于哪种内容类型：

#### 传播款
**特征**：
- 情绪驱动（震惊、愤慨、共鸣、暖心）
- 前3秒必须制造反转或打脸
- 适合转发、评论互动
- 信息密度适中，以故事/案例为主

**适用场景**：热点话题、社会现象、误区纠正、反直觉结论

**判断标准**：用户看完第一句，会不会想继续看？看完整篇，会不会想转发给人？

#### 收藏款
**特征**：
- 信息密度高（干货多、结构清晰）
- 适合收藏备用
- 列表式/步骤式结构
- 实操指导性强

**适用场景**：方法论、操作指南、清单、系统讲解

**判断标准**：用户看完会不会想收藏？这个信息以后会用到吗？

---

### 第四步：素材整理

**目的**：在正式创作前，把所有素材按论证链排列。

**操作步骤**：
1. 列出所有可用素材（来自事实核查 + 采访回答）
2. 按"论证链"排序：核心结论→支撑论据→具体案例/数据
3. 标注每条素材的来源等级（A/B/C）
4. 删除C级以下素材，或将其转化为"有人说..."式的软性表述

**素材卡片格式**：
```
[素材1] 核心结论
内容：...
来源：[URL]（A级）
用途：开头打脸/中间支撑/结尾升华

[素材2] 支撑数据
内容：...
来源：[URL]（B级）
用途：第二段佐证
```

---

### 第五步：正文创作

**必须满足的创作要求**：

#### 口语化标准
- **口语标记词密度**：≥2次/100字
- 常见口语标记词：说白了、换句话说、你想想、说真的、问题是、关键在于、说到底、你知道吗、其实啊、说实话
- 禁止书面语开头：禁止"随着...的不断发展"、"在...的大背景下"

#### 活人感嵌入
- 每篇≥1处"活人感"内容：创作者自己的经历、判断、情绪
- 格式示例：
  - "我在门诊经常遇到这种情况..."
  - "说实话，这个我一开始也搞错过..."
  - "上个月有个患者问我..."

#### 专业术语处理
- **所有**专业术语必须配翻译，不允许裸露术语
- 格式：`[术语]，就是[大白话解释]`
- 示例：`外泌体，就是细胞分泌出来的一种"信使"小颗粒`

#### 结构规范（传播款）
参见 `spread_template.md`

#### 结构规范（收藏款）
参见 `collect_template.md`

---

### 第六步：平台差异化

在完成通用正文后，生成两个平台版本：

#### 视频号版
- 节奏偏稳，有铺垫空间
- 语气温暖，如"晚辈跟长辈聊天"的感觉
- 时长：1000字以内（约2-3分钟口播）
- 结尾侧重："转给你关心的人"
- 开头可以有2-3句铺垫

详见 `platform_diff.md` - 视频号规范

#### 抖音版
- 前3秒必须锋利，直接切入冲突/结论
- 砍掉所有铺垫，直接进主题
- 时长：比视频号版压缩15-20%
- 结尾侧重："评论区告诉我你怎么看"
- 节奏快，短句多，停顿少

详见 `platform_diff.md` - 抖音规范

---

### 第七步：合规自检 + 9件套交付

#### 合规自检（必须逐条检查）

以下任何一条命中 = 打回重写，不允许"整体通过"的笼统判断：

| 编号 | 红线 | 判断标准 |
|------|------|----------|
| C01 | 诊断性表述 | 出现"你可能是/你这是/根据你说的情况判断..." |
| C02 | 承诺疗效 | 出现"一定能/保证/肯定会好/绝对有效" |
| C03 | 推荐具体品牌 | 出现品牌名/商品名/具体型号 |
| C04 | 虚假专业身份 | 声称未持有的证书/职位/专业资质 |
| C05 | 未验证数据 | 具体数字无来源URL |
| C06 | 歪曲政策 | 对政策文件的不准确引用/断章取义 |

**合规输出格式**：
```
合规自检结果：
✅ C01 诊断性表述：未发现
✅ C02 承诺疗效：未发现
✅ C03 品牌推荐：未发现
✅ C04 专业身份：已确认创作者持有[资质]
✅ C05 未验证数据：所有数据均有来源
❌ C06 政策引用：第3段"国家规定..."表述需核查 → 已修改
```

#### 9件套交付清单

交付时必须包含以下全部9项，缺一不可：

1. **视频号版脚本**（符合视频号语气和时长要求）
2. **抖音版脚本**（符合抖音节奏和时长要求）
3. **合规自检结果**（逐条，参见上方格式）
4. **素材来源清单**（含可点击链接，标注来源等级）
5. **平台标题建议**（视频号3个 + 抖音3个，各有不同）
6. **视频封面标题**（主标题大字+副标题小字，提供2套备选）
7. **简介**（视频号版偏利他感 / 抖音版偏信息密度，各一份）
8. **Tags**（视频号10个 + 抖音10个，覆盖热点词+品类词+栏目词）
9. **首评+评论区引导话术**（视频号偏理性平衡 / 抖音偏锋利直接，各一份）

## 三、风格规则自动注入

每次创作前，执行以下步骤将个人化风格规则注入系统提示：

```python
# 从style_db.json读取高置信度规则
rules = load_style_rules(db_path="shared/style_db.json", threshold=0.6)

# 格式化为prompt补丁
style_patch = format_style_patch(rules)
# 注入到系统提示的末尾
```

风格补丁格式示例：
```
## 创作者风格偏好（从历史改稿中学习）
以下规则已通过创作者多次确认，创作时请遵循：
- [tone] 开头不用反问句，用陈述句+转折制造悬念 (confidence: 0.9)
- [wording] "但是"统一替换为"不过" (confidence: 0.85)
- [length] 视频号版控制在1000字以内 (confidence: 0.7)
```
